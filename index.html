Introduction

This interactive documentation explains the WebSim multiplayer capabilities, providing comprehensive details about WebSocket connections, peer management, real-time messaging, and persistent data storage. This guide will help you understand how to build rich, real-time collaborative experiences with WebSim's powerful multiplayer features. Whether you're building a chat application, a collaborative editor, or a multiplayer game, this documentation will guide you through the process.

Recommended approach: Consider whether your application needs ephemeral events (for real-time updates) or persisted records (for data that needs to survive across sessions), or a combination of both. This will influence your architectural decisions.

WebSocket Connection

The WebsimSocket is the foundation for all multiplayer functionality. It establishes and maintains a real-time connection to the WebSim server:

// Connect to the WebSocket server
const room = new WebsimSocket();

The connection is automatically established when you create a new WebsimSocket instance. You don't need to call any additional methods to open the connection.

Example: Basic setup for a multiplayer application

// Create a WebSocket connection
const room = new WebsimSocket();

// Log when connection is established
room.onmessage = (event) => {
    if (event.data.type === "connected") {
        console.log(`Connected with client ID: ${event.data.clientId}`);
    }
};

Under the hood, WebsimSocket uses standard WebSocket technology but adds additional functionality for peer management, event handling, and persistent storage.

Peers & Clients

Client Information

Every connected user has client information automatically assigned and managed by the WebSim platform:

// Access current client's information
let clientId = room.party.client.id;         // Unique identifier for this client
let username = room.party.client.username;   // Username from WebSim account
console.log(clientId, username);

Important: Client information is automatically handled by the library. You should use:

  • client.id for client-specific logic, networking, and identifying the current user in the room
  • client.username for display purposes and user interface elements

Users are already authenticated with WebSim - there's no need to implement additional authentication or request usernames.

Connected Peers

The peers object contains information about all connected clients, including the current client:

// Access all connected peers (including yourself)
for (const clientId in room.party.peers) {
    const { username } = room.party.peers[clientId];
    console.log(`Client ID: ${clientId}, Username: ${username}`);
    
    // Check if this is the current client
    const isCurrentClient = clientId === room.party.client.id;
    if (isCurrentClient) {
        console.log("This is the current client");
    }
}

// Subscribe to peer changes (connections and disconnections)
room.party.subscribe((peers) => {
    console.log("Peer list updated!");
    console.log(`Total peers: ${Object.keys(peers).length}`);
    
    for (const clientId in peers) {
        const { username } = peers[clientId];
        console.log(`Connected peer: ${username}`);
    }
});

Example: Creating a real-time user list

// Create a function to update the UI with the current user list
function updateUserList(peers) {
    const userList = document.getElementById('user-list');
    userList.innerHTML = '';
    
    for (const clientId in peers) {
        const { username } = peers[clientId];
        const listItem = document.createElement('li');
        
        // Highlight the current user
        if (clientId === room.party.client.id) {
            listItem.innerHTML = `${username} (You)`;
        } else {
            listItem.textContent = username;
        }
        
        userList.appendChild(listItem);
    }
}

// Initial user list update
updateUserList(room.party.peers);

// Keep the user list updated
room.party.subscribe(updateUserList);

Events

Events are ephemeral messages that are exchanged between clients in real-time but are not persisted after delivery. They're ideal for:

  • Real-time position updates in games
  • Cursor positions in collaborative editors
  • Transient notifications and status updates
  • Any data that doesn't need to be stored permanently

Event Structure

Events have the following structure:

{
  type: string;       // The event type (required)
  echo?: boolean;     // Whether the sender receives the event (default: true)
  clientId: string;   // Automatically added: ID of the sending client
  username: string;   // Automatically added: Username of the sending client
  // ... additional custom data
}

Sending Events

Use the send method to broadcast events to all connected clients:

// Send a custom event
room.send({
    type: "playerMove",     // Custom event type
    echo: true,             // Whether the sender receives the event (default: true)
    // Additional event data
    position: { x: 100, y: 200 },
    direction: "right",
    speed: 5,
    timestamp: Date.now(),
});

Example: Sending mouse position updates

// Track mouse movement and broadcast to other clients
document.addEventListener('mousemove', (event) => {
    // Throttle updates to avoid flooding the connection
    if (!lastUpdateTime || Date.now() - lastUpdateTime > 50) {
        room.send({
            type: "mouseMove",
            x: event.clientX,
            y: event.clientY,
            echo: false,  // Don't send back to the sender
        });
        lastUpdateTime = Date.now();
    }
});

Handling Events

Use the onmessage event handler to process incoming events:

// Handle incoming events
room.onmessage = (event) => {
    const data = event.data;
    
    switch (data.type) {
        // Built-in events
        case "connected":
            console.log(`New client connected: ${data.username} (${data.clientId})`);
            // Initialize the new client with current state
            break;
            
        case "disconnected":
            console.log(`Client disconnected: ${data.username} (${data.clientId})`);
            // Clean up any resources associated with the client
            break;
            
        // Custom events
        case "playerMove":
            // Update the player's position in the game
            updatePlayerPosition(data.clientId, data.position);
            console.log(`Player ${data.username} moved to (${data.position.x}, ${data.position.y})`);
            console.log(`Direction: ${data.direction}, Speed: ${data.speed}`);
            break;
            
        case "chatMessage":
            // Display the chat message
            addChatMessage(data.username, data.message, data.timestamp);
            break;
            
        default:
            console.log("Received unknown event:", data);
    }
};

Best practices for event handling:

  • Always check the event type before processing
  • Consider using separate handler functions for complex event types
  • Remember that events include clientId and username automatically
  • For high-frequency events (like position updates), consider throttling to reduce network traffic

Persistent Records

Unlike ephemeral events, records are persistent and remain available even after clients disconnect. They're suitable for:

  • Chat messages that need to persist across sessions
  • User-generated content like posts, comments, or annotations
  • Game state that needs to be preserved
  • Any data that should be retrievable for new users joining later

Record Structure

Records have the following structure:

{
  type: string;       // Collection type (handled by the collection name)
  id: string;         // Unique identifier (automatically generated)
  username: string;   // Creator's username (automatically added)
  created_at: string; // UTC timestamp (automatically added)
  // ... additional custom data
}

Creating Records

Use the create method on a collection to add new records:

// Create a new post record
let post = await room.collection('post').create({
    title: "My First Post",
    message: "Hello, persistent world!",
    tags: ["introduction", "hello"],
    visibility: "public",
});

console.log(`Created post with ID: ${post.id}`);
console.log(`Created by: ${post.username}`);
console.log(`Created at: ${post.created_at}`);

Important: Records automatically include:

  • id - Unique identifier (UUID format)
  • username - Creator's username (from WebSim account)
  • created_at - UTC timestamp of creation

You don't need to provide these fields when creating records; they're automatically handled by the system.

Retrieving Records

Records can be retrieved from collections with various query options:

// Get all records from the 'post' collection
let allPosts = room.collection('post').getList();

// Filter records by a specific field value
let userPosts = room.collection('post').filter({ username: "specificUsername" }).getList();

// Get only top-level posts (those without a parent)
let topPosts = room.collection('post').filter({ parent_id: null }).getList();

// Combined filtering (AND logic)
let filteredPosts = room.collection('post')
    .filter({ 
        visibility: "public",
        category: "announcements" 
    })
    .getList();

Important notes about retrieving records:

  • getList() always returns records sorted from newest to oldest
  • Use .reverse() on the result if you need oldest-to-newest order
  • The result may be an empty array while data is loading
  • Filtering only supports exact matching (equality) on field values
  • Multiple filter conditions are combined with AND logic

Schema Changes and Versioning

When making significant changes to your record structure, use versioned collection names:

// Original collection
let posts = room.collection('post').getList();

// When changing the schema, increment the version number
let postsV2 = room.collection('post_v2').getList();

This approach ensures backward compatibility and prevents data corruption when changing record schemas.

Record Relationships

You can create relationships between records by referencing IDs:

// Create a parent post
let mainPost = await room.collection('post').create({
    message: "Main post content",
});

// Create a comment related to the post
let comment = await room.collection('comment').create({
    post_id: mainPost.id,
    message: "This is a comment on the main post",
});

// Create a nested reply
let reply = await room.collection('comment').create({
    post_id: mainPost.id,
    parent_id: comment.id,
    message: "This is a reply to the comment",
});

// Query the entire comment thread for a post
let allComments = room.collection('comment')
    .filter({ post_id: mainPost.id })
    .getList();

// Query only direct comments (not replies)
let directComments = room.collection('comment')
    .filter({ 
        post_id: mainPost.id,
        parent_id: null 
    })
    .getList();

// Query replies to a specific comment
let commentReplies = room.collection('comment')
    .filter({ parent_id: comment.id })
    .getList();

        .filter({ 
            post_id: postId,
            username: currentUsername

Updating & Deleting Records

Users can only update or delete records they created:

// Update a record (can only update your own records)
await room.collection('post').update(post.id, {
    message: "Updated content",
    edited: true,
    last_edited_at: new Date().toISOString()
});

// Delete a record (can only delete your own records)
await room.collection('post').delete(post.id);

Permissions: The system automatically enforces that users can only update or delete records they created. Attempting to modify another user's record will fail.

Best practice is to handle these operations with proper error handling:

try {
    await room.collection('post').update(post.id, {
        message: "Updated content"
    });
    console.log("Post updated successfully");
} catch (error) {
    console.error("Failed to update post:", error);
    // Display appropriate message to user
}

Subscribing to Record Changes

Use subscriptions to keep your UI in sync with real-time record changes:

// Subscribe to all posts
room.collection('post').subscribe(function (posts) {
    console.log("Posts updated:", posts.length);
    updatePostsUI(posts);
});

// Subscribe to filtered posts
room.collection('post')
    .filter({ category: "announcements" })
    .subscribe(function (announcements) {
        console.log("Announcements updated:", announcements.length);
        updateAnnouncementsUI(announcements);
    });

// Store the unsubscribe function when needed
const unsubscribe = room.collection('post').subscribe(function (posts) {
    // Update UI with posts
});

// Later, when no longer needed (e.g., component unmount)
unsubscribe();

Subscription best practices:

  • Subscriptions fire immediately with the current data and then on every change
  • Updates are received whenever any client creates, updates, or deletes a record
  • Avoid expensive operations in subscription callbacks as they may run frequently
  • Remember to unsubscribe when the subscription is no longer needed (e.g., when navigating away)

// Render all comments and set up live updates
function initializeComments() {
    // Subscribe to comment changes
    room.collection('comment').subscribe(comments => {
        // Group comments by parent_id
        const commentMap = {};
        const topLevelComments = [];
        
        comments.forEach(comment => {
            if (!comment.parent_id) {
                topLevelComments.push(comment);
            } else {
                if (!commentMap[comment.parent_id]) {
                    commentMap[comment.parent_id] = [];
                }
                commentMap[comment.parent_id].push(comment);
            }
        });
        
        // Clear the container
        commentsContainer.innerHTML = '';
        
        // Render top-level comments with their replies
        topLevelComments.forEach(comment => {
            const replies = commentMap[comment.id] || [];
            const commentEl = renderComment(comment, replies);
            commentsContainer.appendChild(commentEl);
        });
    });
}

File Upload

WebSim provides a straightforward API for uploading files to secure cloud storage:

// Upload a file to WebSim's storage
async function uploadFile(file) {
    try {
        // Upload file and get the URL
        const url = await websim.upload(file);
        console.log("File uploaded successfully:", url);
        
        // The URL can be used directly in your application
        return url;
    } catch (error) {
        console.error('Error uploading file:', error);
        throw error; // Re-throw to handle in the calling function
    }
}

Supported file types: WebSim supports common file types including images (PNG, JPEG, GIF, WebP), audio (MP3, WAV, OGG), documents (PDF), and more.

File size limits: There are reasonable limits on file sizes to ensure performance. For extremely large files, consider alternative solutions.

        uploadStatus.textContent = `Upload failed: ${error.message}`;

    }
});

LLM Integration

WebSim provides powerful AI capabilities through language model integration, allowing you to build intelligent features directly into your applications.

Basic AI Chat

Implement conversational AI interactions with proper history management:

// Maintain conversation history
let conversationHistory = [];

// Add a user message to the conversation
function addUserMessage(content) {
    const userMessage = {
        role: "user",
        content: content
    };
    conversationHistory.push(userMessage);
    
    // Keep conversation history at a reasonable length
    // to prevent token limits and improve performance
    conversationHistory = conversationHistory.slice(-10);
    
    return userMessage;
}

// Get AI response based on the conversation history
async function getAIResponse(systemPrompt = "You are a helpful assistant.") {
    try {
        // Call the language model with appropriate context
        const completion = await websim.chat.completions.create({
            messages: [
                {
                    role: "system",
                    content: systemPrompt
                },
                ...conversationHistory
            ],
        });
        
        // Extract and save the response
        const aiMessage = completion;
        conversationHistory.push(aiMessage);
        
        return aiMessage.content;
    } catch (error) {
        console.error("Error getting AI response:", error);
        throw error;
    }
}

Resource Type URL Pattern Description
